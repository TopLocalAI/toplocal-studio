# Audio（语音）模块本地实测：ASR 与 TTS

- 测试日期：2026-09-23
- 机器：MacBook Pro M5 Pro，64 GB 统一内存
- 引擎：audio.cpp `487800f5`，Metal 后端与 CPU 后端各测一遍
- 所有模型都用 Q8 GGUF

## 结论

- **一个 audio.cpp 引擎就能覆盖语音识别、语音合成、声音克隆和音乐生成。** 它是 C++ 写的，不需要 Python，只依赖系统框架。唯一的例外是 Kokoro 的英文发音，要依赖 eSpeak-ng，见下文"坑"。
- **语音识别**
  - **默认用 Qwen3-ASR-0.6B**，内存 1.9 GB，GPU 上 30–60 倍实时。
  - **高精度档用 Qwen3-ASR-1.7B**，内存 3 GB，GPU 上 20–40 倍实时。所有测试集里它都最准，方言和噪声场景也最稳。
  - **极速或低配档用 SenseVoice-Small**，内存只要 0.5 GB，GPU 上约 65 倍实时，**纯 CPU 也有约 40 倍实时**。缺点是方言和口音的错误明显更多。
  - **Fun-ASR-Nano 不推荐**：在加了噪声的普通话上错误率高达 42%，在所有模型里最差。
- **语音合成**
  - **默认用 Qwen3-TTS-0.6B**。它必须提供一段参考音，内置几个预设音色即可，同时也就具备了声音克隆能力。中文、英文、中英混说、粤语都读得几乎全对，GPU 上约 3 倍实时，纯 CPU 约 1 倍实时。
  - **极速档用 Kokoro-82M**。GPU 上 12 倍实时，纯 CPU 2.3 倍实时，内存不到 1 GB。缺点有三：会漏读不认识的英文词，比如跳过了 "PPT"；年份会读成"二千零二十六年"；英文发音依赖 eSpeak-ng。
  - **CosyVoice3 只作备选**。中英文效果很好，但粤语错误率 37.5%，有一次还凭空读出了原文没有的"金眼"两个字，而且纯 CPU 下只有 0.4 倍实时。

## 语音识别测试集

| 测试集 | 内容 | 来源 |
|---|---|---|
| KeSpeech | 9 种方言各 12 条，共 108 条，10.7 分钟 | KeSpeech 测试集分片 |
| 粤语 | 30 条，2.3 分钟 | hon9kon9ize/yue_asr_eval_dataset |
| 中文长音频 | 60 条普通话拼接成一段，6.5 分钟 | KeSpeech 普通话 |
| 英文长音频 | 73 条拼接成一段，8.5 分钟 | LibriSpeech 验证集样例 |
| 加噪版 | 上面两段长音频各加 5 dB 信噪比的白噪声 | 自己生成 |

打分方式：
- 中文和粤语算字错率。打分前先把繁体转成简体、阿拉伯数字转成中文数字，并去掉标点。
- 英文算词错率。
- 语言设为自动识别，和产品里的真实用法一致。
- ITN（把"一百五十"写成"150"这类转换）在支持关闭的模型上都关掉。

## 语音合成结果

测试方法：把合成出来的语音交给 Qwen3-ASR-1.7B 转写回文字，和原文比较，算出"复述错误率"。这只能衡量读得清不清楚、有没有读错。音色像不像、自然不自然，需要人来听。

| 模型 | 中文新闻（带数字和日期） | 英文 | 中英混说 | 粤语 | GPU 实时倍率 | CPU 实时倍率 | 内存 |
|---|---:|---:|---:|---:|---:|---:|---:|
| **Qwen3-TTS-0.6B（克隆）** | 1.9 | 0.0 | 0.0 | **4.2** | 2.6–3.4× | 1.0× | 3.1–3.6 GB |
| CosyVoice3（克隆） | 3.7（凭空读出"金眼"） | 0.0 | 0.0 | ❌ 37.5 | 2.9–4.2× | 0.4× | 3.2 GB |
| **Kokoro-82M（预设音色）** | 1.9（年份读成"二千零二十六年"） | 需要 eSpeak-ng，未测 | 8.6（跳过了 "PPT"） | 不支持 | **12.4–12.8×** | **2.3–2.5×** | 0.9 GB |

参考音用的是 SenseVoice 样例录音：中文 5.6 秒，粤语 5.1 秒；英文用 audio.cpp 自带的 14 秒样例。

## 坑

1. **Kokoro 英文要依赖 eSpeak-ng 动态库。** eSpeak-ng 是 GPL-3.0 许可。本项目开源，可以打包，但要注意许可证兼容。另一个办法是英文改用 Qwen3-TTS，Kokoro 只负责中文。
2. **audio.cpp 自带的 VAD 资源用的是相对路径。** 必须在 audio.cpp 目录下运行，或者自己打包好 `assets/framework/models/silero_vad`。
3. **CLI 的输出流不能合并。** 把 stdout 和 stderr 写进同一个文件时，Metal 后端的日志会插进长文本的中间，导致长音频转写结果被截断。这件事一度被误判成"模型漏识别 35%"。stdout 和 stderr 必须分开保存。
4. **批量模式会改文件名。** 用批量模式时，文件名里的 `.` 会被替换成 `_`，打分脚本需要自己映射回来。

## 复现

```bash
uv run --with pyarrow --with soundfile --with numpy python audio/build_testsets.py   # 需要先下载 parquet 分片，见脚本说明
audio/run_asr.sh qwen3asr-0.6b kespeech          # 加 BACKEND=cpu 可测纯 CPU
uv run --with jiwer --with opencc-python-reimplemented --with cn2an python audio/score_asr.py
audio/run_tts.sh qwen3tts-0.6b zh_news [cpu]
```
